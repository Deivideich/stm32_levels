# 001 — Where does a variable live, and for how long?

**Level 1 · size M · concept: storage duration**
Starter: `001_variable_lifetime.c` · Notes: `notes/001.md` · Run: `make 001`

## Why this matters in firmware

On a PC, reading a variable that no longer exists usually "just works" or ends in a clear crash.
On a microcontroller there is no operating system to catch it. The stack is a small fixed region
shared by every function call **and every interrupt**, and the same bytes are reused all the time.
A bug of this kind looks like "this value changes by itself, but only sometimes", typically when an
interrupt fires. Before you can reason about that, you need a precise picture of where each
variable lives and how long its memory lasts.

## Words you need

- **Storage duration**: how long a variable's memory exists. *Automatic* (a local variable): from
  entering its block until leaving it. *Static*: the whole run of the program.
- **Stack**: where automatic variables live. A call pushes a frame, the return pops it. "Popped" does
  **not** mean erased; it means "free to be reused".
- **`.data` / `.bss`**: where static variables live. `.data` holds those with a non-zero initial value,
  `.bss` those that start at zero. In firmware their addresses are fixed at link time.
- **Undefined behaviour (UB)**: the language promises nothing. The program may crash, may appear to
  work, or may work today and break after an unrelated change.

## Hints (open only when stuck)

<details><summary>Hint 1 — the 42 and the 7</summary>

The stack is reused. When `remember_local` returns, its frame is free. The next function with the same
shape (`reuse_stack`) gets a frame at the same place, so its local lands on the same address.
</details>

<details><summary>Hint 2 — reading <code>nm</code></summary>

Lowercase letter = symbol private to the file, uppercase = exported. `b` = `.bss`, `d` = `.data`.
A static variable inside a function appears with a numeric suffix (for example `n.0`).
Automatic variables never appear in `nm`: they are created at run time on the stack.
</details>

<details><summary>Hint 3 — why only -O1 and above complain</summary>

At `-O0` the compiler looks at one function at a time. From `-O1` up it can see through `keep()` and
follow the pointer, so it notices that `local` is gone when `main` reads it.
</details>
